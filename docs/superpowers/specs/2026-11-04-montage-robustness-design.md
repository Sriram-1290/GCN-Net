# Montage robustness: does a graph model survive missing and reduced electrode sets better than ShallowConvNet?

*Design, 2026-11-04. Experiments A and B from the conversation of that date; C (cross-dataset
transfer to BCI IV-2a) is deliberately out of scope and gets its own design if A/B succeed.*

## 1. Intent

On the full 64-electrode task, our graph model and ShallowConvNet tie once both are
pre-trained (PTG-gbp 0.7301 vs PTG-shallow 0.7369, difference +0.0068 [−0.0022, +0.0155];
`project_documentation.md` §9.17). Every spatial operator tried converges to the same
answer, and four attempts to move the ceiling measured nothing (§9.19, §9.21, §9.23, §9.17).
The team wants a **clear, defensible win** for a research paper, not a tie.

The one place a graph model is *structurally* different is the spatial stage. ShallowConvNet's
spatial convolution has one weight per electrode in a fixed order, so it only runs on the exact
64 channels it was trained on. A Chebyshev graph convolution learns weights `Θ_k` that are
shared across nodes and applied through the graph, so the same filter can run on any subset of
electrodes for which a graph exists. If that flexibility is real, a graph model trained once on
the full cap should degrade more gracefully than ShallowConvNet when electrodes are missing at
test time, or when it is deployed on a smaller cap.

This design tests exactly that, under rules fixed before any run, against the strongest fair
baseline.

## 2. Goals, non-goals, anti-goals

**Goals**
- Measure within-family accuracy of a graph-convolution model and of ShallowConvNet, both
  pre-trained identically, when trained on the full 64 channels and tested on degraded or
  reduced electrode sets.
- Decide, by a rule fixed in advance, whether the graph model wins clearly.

**Non-goals**
- Raising full-montage accuracy. The full-montage number of the new model is reported, not
  optimised.
- Hyperparameter tuning of either model. Both keep the settings of the PTG arms.
- A second dataset (experiment C).
- Unflagged noisy channels (a corrupted channel the system does not know is bad). Deferred:
  it is a different question (detection) and would double the condition count.

**Anti-goals — outcomes that would count as failure even if a number came out ahead**
- A win against a baseline that was not given the standard repair for missing channels.
- A win found by choosing conditions, thresholds or regions after seeing results.
- A win that exists only on the 20 development subjects.
- A win that disappears as soon as ShallowConvNet is trained with channel dropout (the
  obvious reviewer objection — see Phase 2).

## 3. Models

| ID | Model | Pre-training | How it handles missing channels at test time |
|---|---|---|---|
| **M1** | `graphbp`, `spatial="graph"` (Chebyshev, *K* = 2, one layer, no node pooling) with a **region-pooled readout** (§3.1) | PTG: 10 subject-disjoint groups, identical to PTG-shallow | Drops the missing nodes; the Chebyshev basis is rebuilt on the induced subgraph of the source graph |
| **M2** | ShallowConvNet | PTG, reusing the cached source models `runs/source_models/src-PTG-shallow-*` | Missing channels reconstructed by spherical-spline interpolation (MNE, standard 10-05 positions), restoring all 64 inputs |
| M1-interp | M1 | as M1 | Interpolation instead of node dropping — isolates whether any robustness comes from dropping nodes or from the architecture |
| M2-zero | M2 | as M2 | Missing channels set to zero — the naive baseline, reported for context only |

M1-interp and M2-zero are secondary and never part of the win decision.

### 3.1 Region-pooled readout (the only architectural change)

`GraphBandPowerNet`'s classifier is `Linear(M × F_s, n_classes)`, one weight per electrode per
filter, which welds it to 64 channels exactly as ShallowConvNet's spatial layer is welded.
Pooling over all nodes would remove that, but would also remove *where* power changes, and
left-versus-right imagery is decided by location. The readout therefore pools log band power
within **fixed anatomical regions** and classifies the region × filter features.

- **Regions:** 9 = {left, midline, right} × {frontal, central, posterior}, assigned from the
  10-10 electrode *name*, so the rule needs no judgement *(my call)*:
  - **column:** suffix `z` → midline; odd number → left; even number → right;
  - **row:** prefixes Fp, AF, F, FC, FT → frontal; C, T, CP, TP → central (T9 and T10
    included); P, PO, O, Iz → posterior.
  
  The resulting 64-row table is generated by code, printed into the pre-registration (§6)
  **before any run**, and never changed. Checked against the montages: the IV-2a set
  leaves every region occupied (frontal: FC3, FC1 | Fz, FCz | FC2, FC4; central: C5, C3, C1,
  CP3, CP1 | Cz, CPz | C2, C4, C6, CP2, CP4; posterior: P1 | Pz, POz | P2), and so does the
  10-20 set.
- **Pooling:** mean of the log band-power features of the nodes present in each region, per
  spatial filter: 9 × 40 = 360 features into the linear classifier. Region membership is
  mapped through any node permutation the graph code applies.
- **Empty region:** the smallest region is midline-central (Cz, CPz), which a random 25 %
  removal empties about 6 % of the time. **Random and clustered draws that empty any region
  are rejected and redrawn** *(my call)*. The rejection depends only on the pattern, never on
  the data, and the same accepted pattern is used for M1 and M2, so the condition stays
  paired and fair. The zero-feature fallback is kept only as a guard and is never reached in
  a scored condition.

The normalisation layer (`BatchNorm1d` over spatial filters) is already independent of the
channel count and is unchanged.

## 4. Test conditions

Both models are trained (pre-trained and fine-tuned) on all 64 channels. Every condition is
applied **only at test time**, to the held-out fold of each subject, with the same channel
pattern for M1 and M2 (paired).

| Condition | Electrodes available | Role |
|---|---|---|
| **Full** | all 64 | Reference; also measures what the region readout costs |
| **IV-2a montage** | the 22 BCI IV-2a channels: Fz, FC3, FC1, FCz, FC2, FC4, C5, C3, C1, Cz, C2, C4, C6, CP3, CP1, CPz, CP2, CP4, P1, Pz, P2, POz | **Primary 1** |
| **Random 25 %** | 48 of 64; 16 removed uniformly at random | **Primary 2** |
| 10-20 montage | the 19 classical 10-20 channels | Secondary |
| Random 10 %, 50 % | 58 or 32 of 64 | Secondary |
| Clustered 8, 16 | the 8 or 16 nearest neighbours of a random electrode removed | Secondary |

Random and clustered patterns use 10 independent draws per (subject, fold), seeded from
(subject, fold, draw) so they are identical across models and reproducible, with the
empty-region rejection of §3.1. Per-fold accuracy is the mean over draws.

### 4.1 Re-referencing: every condition is what a real cap would record *(my call)*

The cached data are average-referenced over all 64 channels, so simply masking channels
afterwards would leave every remaining channel carrying the missing ones through the
reference. A 22-channel cap does not record that. Therefore:

- A new cache variant stores the same epochs **before** the common average reference
  (band-pass, epoching and everything else unchanged). Average referencing and band-pass
  filtering are both linear, one across channels and one across time, so they commute.
  Re-referencing the new cache over all 64 channels must reproduce the existing cache to
  floating-point tolerance. This is checked, and one existing PTG-shallow fold is re-run
  bit-for-bit, before anything else.
- In every condition, the test window is **re-referenced to the average of the electrodes
  that are present**.
- **M1:** for each condition the graph and the per-channel standardiser are recomputed from
  **source subjects' data re-referenced over the same electrode subset**. This is the
  representation the model would have been given on that cap, and it still contains no target
  data. The design is therefore no longer "induced subgraph of the 64-channel graph". Training
  is unchanged: full 64, average reference, exactly as in PTG.
- **M2:** its best-effort repair, in this order: re-reference the available electrodes to their
  average; reconstruct the missing ones by spherical-spline interpolation; re-reference all 64
  to their average; standardise with the source statistics. This restores the input
  ShallowConvNet was trained on as closely as the standard tools allow.

## 5. Leakage rules (unchanged from the PTG arms, plus three)

- The graph and the standardiser are fitted on **source subjects only**, exactly as in PTG.
- For M1 under a reduced condition, the graph and standardiser are recomputed from source
  subjects re-referenced over the same subset (§4.1). No target data, test or training,
  enters either.
- For M2, interpolation uses only electrode positions, in the order fixed in §4.1.
- Channel patterns, and the rejection of patterns that empty a region, depend only on seeds
  and the region table, never on the data.

## 6. Pre-registration and decision rule

Before the first run, a new section, §9.24, is added to `docs/project_documentation.md` and
committed. It contains the region table, the condition list above, predictions, and this rule.

**Clear win** for M1 over M2 on a primary condition requires all four:
1. paired mean difference in within-family accuracy **≥ 0.020** (the design's minimum
   detectable difference, §17.2);
2. 95 % bootstrap CI excluding zero;
3. Holm-corrected *p* < 0.05 across the **two** primary conditions;
4. M1 ahead on a **majority of subjects**.

**And one guard on the full montage** *(my call)*: if M1 trails M2 on the Full condition by
more than 0.020, which would be a detectable loss, any robustness advantage is reported as a
**trade-off**, not as a clear win. A model that is more robust but worse on a complete cap
does not meet "a clear win". The comparison with PTG-gbp's 0.7301 is reported for context and
is not part of the rule.

Everything else is reported as measured, including a loss. Secondary conditions are
exploratory and labelled so.

## 7. Phases

**Phase 1 — development (20 subjects, S001–S020).** Implement §3.1 and the test-time
conditions, pre-register, run M1 and M2 on the development subjects. Exploratory. Report the
result whatever it is.

**Phase 2 — the robustness-training objection (development set).** Runs only if Phase 1 shows
M1 ahead on a primary condition by at least the 0.020 margin. All settings below are my
calls, fixed in §9.24 before Phase 1 starts, so they cannot be chosen in the light of
Phase 1:

- **Both models train with channel dropout in pre-training *and* fine-tuning.** Dropout during
  fine-tuning alone, on ~36 trials, would be a weak version of the baseline. This costs two new
  sets of 20 source models, about 5 h each.
- **Rate:** each training window independently loses 25 % of its electrodes, matching
  Primary 2. Fixed, not tuned.
- **Each model trains the way it handles missing channels at test time.** M1 drops the nodes,
  with the graph rebuilt for that subset; the Chebyshev basis with the fixed λ<sub>max</sub> = 2
  is a few 64 × 64 products per batch. M2 zero-fills, the standard form of channel dropout.
- **M2 is tested both with interpolation and with zeros, and its better score counts.** This
  biases the comparison towards the baseline, deliberately.
- **"Survives"** means M1-with-dropout beats M2-with-dropout (at its better repair) on the
  same primary condition, by the same four criteria of §6.

**Phase 3 — confirmation.** Runs only if a win survives Phase 2, using the Phase 2
configuration (both models trained with dropout), with no changes, on the 83 subjects outside
the development set. This is the result that goes in the paper. The 103-subject figure may be
shown alongside it.

If Phase 1 or Phase 2 fails the bar, the experiment stops and is written up as a null, as the
four previous challengers were.

## 8. Constraints

- **Compute.** M1 needs a new grouped pre-training (20 source models, about 5 h at the
  measured 14.9 min each) plus fine-tuning. M2 reuses its cached source models and needs only
  fine-tuning. The test-time conditions add evaluation passes, plus per-condition graph and
  standardiser fits on source data, but no training. Phase 2, if reached, adds two
  pre-trainings, about 10 h. One new cache variant is needed (§4.1). Runs go in the
  background and must not block the review paper due before Review-2 (about 15 days).
- **Hardware.** Batch 256 stays as is (`CLAUDE.md`: near the `graphbp` activation ceiling).
- **Logging.** One row per (arm, condition, problem, subject, fold) in `runs/experiments.jsonl`,
  with new tags (proposed: `PTG-chebrp-binary-*` for M1's clean run, `ROB-<model>-<condition>-*`
  for degraded conditions). The completeness check refuses to aggregate a tag below its fold
  target.
- **Code.** Small, tested changes: a region-readout option in `GraphBandPowerNet`, a function
  that rebuilds the Chebyshev basis for a node subset, a channel-pattern generator, an
  interpolation wrapper, and an evaluation hook in `run_pretrain_finetune.py`. Each gets unit
  tests on synthetic inputs, in keeping with the existing 337.

## 9. Left to the builder

- Exact tag strings and file layout of the new code.
- How the evaluation hook is structured inside `run_pretrain_finetune.py`, provided the clean
  fine-tuning path stays bit-identical when no condition is requested (verified by re-running
  one existing PTG-shallow fold).
- Whether M1-interp and M2-zero run in Phase 1 or are added later.
- Known details from the design review:
  - M2's cached source models assume the full 103-subject grouping (index mod 10), with
    targets restricted to S001–S020. Their cache filenames embed the old PTG tag, so the new
    runs must load them explicitly rather than through `--resume` on that tag.
  - Fine-tuned models are not saved, so M2 is fine-tuned again; its clean Full score must
    reproduce PTG-shallow's logged per-fold values for the development subjects.

## 10. Risks, stated in advance

- The region readout may cost accuracy on the full montage. This is reported, and a large loss
  would itself argue against the design.
- Spherical-spline interpolation is strong when few channels are missing, so a win is least
  likely at 10 % and most likely at the 22- and 19-channel montages and at 50 %.
- The whole experiment may produce a null. That would be the fifth measured challenger to the
  ~0.73 picture and is a reportable result.
